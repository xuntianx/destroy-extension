## 三、本轮 4 个问题

### P1-1 白芯是一条恒定 13px 高、长达 39% 的直线高光；火焰根部被 10px 封顶

- 位置：`src/content/breath-fx.ts:48` `const root = Math.max(4, Math.min(10, width * 0.22));`、`:54` `core` 的 y 全部写成 `root*0.65 / root*0.3`（**绝对像素，不经过 `y()`**）。
- 证据：`width*0.22` 在 400px 时 =16.7、650px 时 =27、900px 时 =37.4，**全部被 `min(…,10)` 压回 10**。所以无论火焰多大，根部恒为 20px 高、白芯恒为 13px 高。在 900px 长度下白芯是 351×13 ≈ **27:1 的直线**。图上就是从嘴部斜向右上那道贯穿到约 45% 的亮白细条——它是整幅最亮的元素，也是上一版"直线感"唯一的残留。同时这条封顶让「根白梢细」在实际尺寸下根本没实现：根部反而是最窄的地方，于是近嘴 1/4 段是一根细直楔形"柄"，后面才炸开成"叶头"。
- 用户会看到：一团好看的火，但中间横着一道像激光/刀刃的白线；火与嘴之间有一小段细杆。
- 最小改法（两行）：① `const root = Math.max(6, Math.min(18, width * 0.22));`（上限 18 ≈ 28° 开口时的口腔高度，仍不会比嘴宽）；② `core` 的根端改用 `y(±0.18)`、在 `x(0.39)` 收为 0，即 `M 0 ${y(-0.18)} C ${x(0.12)} ${y(-0.15)} ${x(0.24)} ${y(-0.07)} ${x(0.39)} 0 C …`。让白芯变成随火焰缩放的楔形火心。
- 通过标准：650px 与 900px 各一帧，白芯最宽处 ≥ 全火高度的 12%，且宽度从根到 39% **单调递减**；白芯长宽比 ≤ 8:1；火焰根部高度 ≥ 口腔开口高度的 0.7 倍。

### P1-2 900px 时火焰放大到 900×498，6 个大平滑裂片读成枫叶，角色被压过

- 位置：`breath-fx.ts:47` `Math.min(small ? 85 : 170, length * 0.19)`；`:51` 的火舌簇数固定为上 3 下 3。
- 证据：三档实测总高 223 / 362 / 498px，而角色只有 **208px 高、248px 宽**。900px 那张里火焰是角色高度的 2.4 倍、面积约 8.6 倍；且因为簇数不变，每个裂片在 900px 时约 170px 高、200px 宽，成为大而平滑的圆瓣——这正是"枫叶/橡树叶"的读法来源。真实卡通火焰变大时是**增加更小的火舌**，不是把同样 6 个瓣等比吹大。400px 和 650px 两张没有这个问题，看着都好。
- 最小改法（二选一，都不破坏"喷到目标"）：① 把上限从 170 降到 **120**（900px → 900×352，2.56:1，仍然厚实，但不再吞掉半屏，角色重新站得住）；② 若要保留体量，则在 `outer` 的每个 `wave(i)` 上叠一层高频小波 `+ Math.sin(p*97 - i*2.2) * 0.07`，让大瓣边缘长出小火舌。建议先做 ①，成本一个数字。
- 通过标准：`mouth→target = 900px` 时火焰总高 ≤ 角色高度的 1.8 倍（≤375px）；上下缘可数出的火舌 ≥ 8 个，其中至少 3 个高度在全火高的 8%~20% 之间（即有大有小）。

### P1-3 火焰朝向没有任何约束：可能近乎垂直从鼻梁射出，扫掠中可能回扫过脸

- 位置：`session.ts:646-667`（开火前站位）与 `:725-738`（扫掠终点插值）；`breath-fx.ts:19-20`（角度 = `atan2(target−mouth)`，无钳制）。
- 证据（代码可判定，**静帧无法证明，导出写死了一个舒服的目标点**）：
  - 站位只用 `targets` 数组里**第一个可见目标**（`:646-654` 的 `find`，不是排序后的），横向让出 300px。而嘴部约在 `left+201`，即嘴到目标中心的**水平距离只有约 99px**。若该目标靠近视口顶部（垂直差 ~440px），`atan2(-440, 99)` ≈ **−77°**，火焰几乎垂直向上，从朝右的吻部侧面射出。
  - 更关键的是 `:725-738` 的扫掠：`end` 在 `visible` 列表（按距嘴远近排序，**不分左右**）之间插值。收尾吐息覆盖的是全部剩余已登记目标，其中必然包含左侧导航、侧栏。当扫掠点移到怪兽身后，`angle` 会转过 90°，火焰被 `wrap()` 旋转后**从嘴部向后覆盖头部与躯干**——这正好违背你明确提的「火焰不应遮掉怪兽辨识度」。
  - 你们说的修复只覆盖了"开火前的初始站位"，没有覆盖开火后的扫掠。
- 最小改法（保住你坚持的"嘴部/命中对应"）：站位改成按垂直差取让位距离 `center - clamp(dy * 0.8, 300, 620)`；并在画火焰前把**绘制方向**钳到朝向半球内（相对朝向 −55°~+25°），`end` 落在钳制后的射线上、距离不变。**命中仍由 `:760-766` 的尘埃圆打在目标真实位置**，所以"打到哪、哪里碎"的对应没有丢，只是火柱不再横穿自己的脸。
- 通过标准：一次真实长页 FINAL_BLAST 的连拍/录屏中，任意一帧火焰与角色包围盒的重叠面积 ≤ 角色面积的 10%，且火焰与朝向的夹角始终 ≤60°。**这条必须要浏览器观察，静帧不算。**

### P2-4 收尾末帧整体偏灰偏淡，像烟不像火

- 位置：`breath-fx.ts:64` 整组 `opacity = min(1, growth*3) * Math.sqrt(fade)`。
- 证据：end−40ms 时 `fade = ease(0.261) = 0.169` → `sqrt(fade) = 0.41`，而 inner = 0.055、core = 0.021 已基本消失。于是最后一眼是一块 41% 不透明的**扁平淡橙剪影**，在米色底上呈浅肉粉，`ending.png` 第三格就是这个观感——形状是火，颜色像烟。
- 最小改法：把整组透明度改成 `Math.min(1, fade * 1.8)`（让末段保持较高不透明度、靠尺寸收缩退场），同时末段填色向深橙偏移，如 `fill="${fade < 0.4 ? '#e2792f' : '#ee9a4b'}"`。
- 通过标准：end−40ms 帧的火焰主色饱和度不低于峰值帧的 70%，整体不透明度 ≥0.6。
