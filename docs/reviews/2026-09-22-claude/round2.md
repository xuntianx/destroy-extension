## 一、视觉审美判断

**整体 6.5 / 10 —— 不通过。**
拆开看：**角色 8 / 10（通过）**，**吐息火焰 5 / 10（不通过）**。

### 角色（8/10，这是本轮最大的好消息）

`overview.png` 让我可以撤销第一轮关于「造型待观察」的保留：

- **在 248×208 实际尺寸下，它确实就是概念图里那只怪兽**。粗黑轮廓、橙色背鳍、奶油腹甲的横向分节、腮红、单侧上翘的獠牙、那对标志性的浓眉——一一对得上，不是"另画了一只"。这在"AI 概念图 → 手写 SVG 分件"的路线里是很容易翻车的一环，这里没翻。
- 五套动作都能一眼读出是什么：`tail 611ms` 的低伏蓄力和 `830ms` 尾巴扫到身体前景，是整组里最有力的两帧；`sleep 875/1750ms` 的闭眼低头很可爱，`2625ms` 淡出干净。
- 扣分处：`claw 610ms` 的命中帧里，前爪几乎没有突破身体轮廓（手臂短、贴在腹前），远看更像"身体前倾"而不是"挥爪劈下"，力量感弱于尾扫。这条不进本轮 Top5（本轮重点是火焰），但在目标 1 上仍是未了项。
- 提醒：`entrance 0ms` 那格角色已完整可见，但我没核对导出脚本是否应用了 `frame.opacity`，**不能据此判定运行时提前露出**。

### 火焰（5/10 —— 比上一版的浅绿直线好很多，但还没到"好看"）

先给用户要的那句直话：**它现在不像纸片，也不像几何图案；但主体像一片被横向拉长的羽毛 / 柳叶，而收尾那 150ms 像一根浅色长矛。**

做对的：
- 配色是对的。橙 `#ee9a4b` / 金 `#ffda80` / 奶白 `#fff8d8` 与背鳍 `#ffb25f→#ee8946`、腹甲 `#fff0c9` 同一家族，**和灰绿橙鳍的卡通画风是统一的**，不刺眼、不塑料。
- **没有遮挡角色辨识度**：`outer` 路径的 x 全为正（`breath-fx.ts:50`），只朝前延伸，四张图里怪兽的脸、眉、獠牙、背鳍全程清楚。这条用户要求**通过**。
- 嘴边蓄力（`748ms` 的小橙光斑 + 三点火星）、余烬、三层结构、runtime/preview 共用同一 renderer —— 方向都是对的。

不够好看的根因（都能在代码里指到）：
1. 它**不是一团火，是一把刀**：一个整体的长锥，边缘只在末端炸开三个尖，中段几乎是两条平行的缓弧。
2. 三层完全同轴同锥，**最白的芯在中后段**，根部反而只有 ±1 宽——亮度走向和真实火（根白、梢碎）相反。
3. 根部是 8px 的针尖，**和怪兽那张几乎没张开的嘴接不上**。
4. 从 1.0s 到 2.1s 轮廓一动不动，只有整体宽度在 ±8% 呼吸。
5. 最后 150ms 退化成一条全长的奶白细线——**正是用户上一轮否决的东西**。

## 二、本轮 5 个主要问题

### P0-A 收尾 150ms 退化成"浅色细直线"，把用户已否决的观感原样带回来

- 位置：`src/content/breath-fx.ts:44`（`fade = ease((end - p)/0.045)`）、`:47`（`width = ... * fade`）、`:62`（三层绘制顺序，`#fff8d8` core 在最上）。
- 证据：`fade` **只乘进 width，不乘 length**。取 `flame-overview.png` 的 3026ms 帧（`motions.ts:7,13`：duration 3400、end 0.9 → p=0.89），`fade = ease(0.222) = 0.126` → 半宽 52×0.126 ≈ 6.5px、整体 opacity 0.126，而长度仍是满值。三层被压进 6px 内，最上层的奶白 core 盖住橙色 outer → 得到图上那条**贯穿到画面外的全长奶白直线**。窗口 = 0.045×3400 = **153ms**，且它是整个吐息用户看到的最后一眼。
- 用户会看到：火焰不是"熄灭"，是"被抽成一根白丝"。
- 最小改法：① 让退场靠**缩回嘴边**而不是变细 —— `const length = Math.max(12, distance * growth) * (0.35 + 0.65 * fade)`；② 让内层先死 —— `inner` 用 `opacity=fade**1.6`、`core` 用 `opacity=fade**2.2`，保证最后可见的是橙色小火苗。两处改动，不新增依赖。
- 通过标准：导出 end 前 40 / 80 / 120ms 三帧 —— 火焰长度单调下降到峰值的 ≤35%；每帧宽长比 ≥ 1:6（即不允许出现"细长条"）；最后一个非空帧的火焰主色相在橙色区（H≈25–35°），不得为奶白。

### P0-B 细节尺度被锁死在 52px，距离一长就拉成羽毛/长矛（运行时比你给的图更严重）

- 位置：`breath-fx.ts:47` `Math.min(small ? 24 : 52, length * 0.18)`；`:48-52` 所有 `x()` 乘 `length`、所有 `y()` 乘 `width`。
- 证据：火舌的**纵向尺寸有 52px 上限，横向尺寸没有上限**，所以每一根火舌都随距离被线性拉平。导出距离 449px 时宽长比已是 **3.2:1**（`flame-46.png` 肉眼可见中段是两条近平行的缓弧）；按运行时常见的 700~900px 计算，同样的 6 个火舌会摊到 **6:1 以上**。这是"像旗子/羽毛"的数学根因，不是观感玄学。
- 最小改法：① 去掉硬顶，`width = clamp(length * 0.3, 26, 120)`；② 同时限长 `length = Math.min(distance, 520)` —— 火焰不需要几何上真的触到目标，命中反馈已经由 `session.ts:760-766` 的逐个尘埃圆承担了。这两行同时改，才能锁住宽长比。
- 通过标准：用 mouth→target 距离 400 / 650 / 900 三种情况各导一帧，**宽长比都落在 1:2.6 ~ 1:3.6**；上缘、下缘各能数出 ≥3 个高度 ≥ 全高 25% 的火舌（现在长距离下只剩末端那一簇）。

### P1-C 三层同轴同锥、最白处在末端 → 像贴纸，不像有体积的火

- 位置：`breath-fx.ts:50 / 51 / 52`（outer / inner / core 共用同一套 `x()`/`y()` 归一化坐标、同一起点、同一收敛方向）；`:62` 的描边 `stroke="#a96337" stroke-width="1.6"`。
- 证据：`core` 的最宽处在 `x(0.42)~x(0.63)`，根部只有 `y(±1)`；也就是**最亮最白的部分在火焰中后段，根部反而最暗最细**——和卡通火焰"根部最白、越远越碎越橙"的常识相反，这是它看起来"平"的主因。另外角色主轮廓是 5.5/620×248 ≈ **2.2 CSS px 的近黑 `#1e3529`**，火焰边线只有 **1.6px 的中棕 `#a96337`**，比角色更细更浅，两者像两套画法。
- 最小改法：① `core` 的 x 范围收到 `0 → 0.45`，根部半高从 `y(±1)` 提到 `y(±0.45)`、末端收细；② 给 `inner`、`core` 的控制点分数各加 3%~5% 的相位偏移，打破三层同轴；③ 描边改 `stroke-width="2.2" stroke="#8c4a20"`。
- 通过标准：单帧上从嘴部到末端取 5 个等距截面，奶白芯宽度**单调递减**；火焰描边与角色主轮廓的视觉粗细差 ≤0.4px。

### P1-D 火焰根部是 8px 针尖，而怪兽"吐息"时嘴几乎没张、身体几乎不动 → 因果读不出来

- 位置：`breath-fx.ts:50` 根部写死 `M 0 -4 ... 0 4`（**与 width 无关的固定 8px**）；`rig.js:260` `rotate(${jaw * 12} 10 42)`；`motions.ts:53-57`（`bodyX = -charge*70` → 屏幕约 7.8 CSS px；`headR = -charge*8`）。
- 证据：`overview.png` 的 breath 行 `1938ms / 2584ms` 与 `flame-46.png` —— 嘴只是一道微张的缝，身体姿态与 `breath 0ms` 的中立姿势几乎没有区别，却从嘴角射出一条比身体还长的火。观感是"火贴在嘴角上"，不是"它喷出来的"。12° 的下颌开合对一次全力吐息太小了。
- 最小改法：① 根部改 `±Math.max(4, width * 0.22)`，并在根部补 2 个包住下颌的小火舌；② 吐息期下颌角度提到 26~30°（把 `jaw * 12` 的系数参数化，只在 breath 用大值，不影响其它动作）；③ `headR` 由 `-charge*8` 改 `-charge*14`，`bodyR` 后仰到 `-charge*6`。
- 通过标准：吐息峰值帧中**口腔开口高度 ≥ 火焰根部高度的 0.8 倍**；该帧头部角度与 neutral 相差 ≥12°；火焰根部与下颌之间无可见空隙。

### P1-E 1.0~2.1s 轮廓完全静止，只有整体宽度在 ±8% 呼吸

- 位置：`breath-fx.ts:25` `wave = Math.sin(p * 58)`，其结果只进 `:47` 的 `width`；outer/inner/core 的控制点全程为常量。
- 证据：`1564ms` 与 `2108ms` 两帧除余烬位置外**轮廓完全一致（544ms 无形变）**。宽度脉动周期约 367ms、幅度 ±8%，且是三层一起等比缩放 —— 这是"整体呼吸"，不是火舌摆动。
- 最小改法：给 outer 上缘 3 个峰、下缘 3 个峰各加独立相位，例如把 `y(-0.92)` 写成 `y(-0.92 + 0.22*Math.sin(p*41 + 1.1))`，6 处各用不同频率/相位。成本是 6 个 `sin`，不新增依赖，仍然确定性可复现。
- 通过标准：导出 1.2 / 1.5 / 1.8 / 2.1s 四帧，相邻两帧任一上缘峰值的 y 差 ≥ 全高 8%。
- **待观察**：静帧只能证明"当前没有形变"。改完之后"火有没有活起来"必须靠实际播放判定，我不会用静帧宣称动态通过。

## 四、verdict

# NEEDS_CHANGES

理由，按你新增的审美必过标准：

1. **P0-A 是审美层面的回归**：吐息的最后 150ms 会重新出现一条浅色细直线，而这正是用户上一轮明确否决的形态。只要它还在，"吐息好看了"就不能算数。
