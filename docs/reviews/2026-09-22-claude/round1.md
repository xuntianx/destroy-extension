# 「摧毁 / Destroy」效果评审（第 1 轮，源码 + 概念图证据）

## 证据范围声明

本轮我只读了源码、`docs/character-concept.png` 与文档。**我没有运行浏览器、没有看到任何由实际 rig 渲染出的关键帧图，也没有试听任何 `.opus`**。因此下面凡涉及「像不像概念图」「力量感够不够」「声音好不好听」的结论，一律标为**待观察**，不冒充视觉/听感验收。`acceptance-report.md` 自己也写明：最终美术、主观试听、真实 Chrome 首次快捷键发声均未完成——我按同样的边界处理。

## 总体评价

骨架层面的工程判断是对的，而且有几处确实做到了「效果导向」而不是「测试导向」：

- 爪击/尾扫的关键帧结构是合格的动作曲线，不是简单来回：爪击 0→340ms 前摇、480→610ms 130ms 内挥出 132°、610→690ms 有 80ms 接触停顿、再分两段回弹（`rig.js:96-146`）；尾扫 830ms 命中后还继续过冲到 1140ms 才回收（`rig.js:147-188`）。**蓄力—接触—回弹的时间设计是成立的**（目标 1 的时间维度合格，造型维度待观察）。
- 脚部补偿的数学是真的成立：`undoBody` 与 `rig-whole` 的旋转中心同为 `(326,459)`，两者相乘恰为单位矩阵（`rig.js:239-265`），所以「脚底漂移 0.00001 px」不是测试作弊，是结构性保证。
- 音频侧的事件设计骨架好于一般水平：120ms 前瞻调度（`audio-cues.ts:15-30`）、命中压低配乐（`mixer.ts:363-368`）、按屏幕 x 做声像、相邻不重复的变体选择（`mixer.ts:340-347`）、限幅器与三条音量总线。
- 问答文案中英双语、与方案逐字对齐，提交校验 + `composing` 守卫 + Enter 不直接提交，**目标 5 基本达标**。

但把「摧毁」当作一次可看的表演来评，**当前最弱的不是角色动作，而是被破坏的页面本身**：真正决定观感的三个时刻——最终吐息、废墟、归位——都在代码里被简化成了「瞬间切状态」。用户会记住的「碎片和废墟」在当前实现中存在时间很短、尺寸很小，最后被一层 93% 不透明底色盖掉。这不是靠调参能糊过去的，需要改几处具体逻辑。

## 问题清单（按影响排序）

### P0-1 最终吐息就是一次机械清屏：内容单帧全部消失，之后还有约 2 秒空转光束

- 位置：`src/content/session.ts` `blast()`（587-664），配合 `src/content/page.ts` `hideTarget()`（132-141）。
- 证据：
  - `pieces` 只在 `single === true` 时由 `fracture()` 产生（641-648）；**收尾吐息 `single=false`，`pieces` 恒为空数组**，即剩余所有目标一片碎片都不生成。
  - 命中帧 `targets.forEach(hideTarget)`（649），而 `hideTarget` 是 `duration:1 / currentTime=1` 的 WAAPI，**opacity 0 在同一帧生效**，几十个元素同时消失。
  - 特效层全程只有一条 `<line>`（636），几何固定、无锥度、无抖动、无尘埃；`frame.glow` 在 `p=0.57` 从 12.5px 直接归 0（`motions.ts:59`）。
  - 时间轴：总时长 4700ms，光束 0.38→0.86（1786→4042ms），命中在 0.57（2679ms）。**命中后还有 1363ms 光束打在一个已经 opacity:0 的元素上（`targets.find` 不过滤已隐藏项，624-627），再加 658ms 什么都不发生的收势。**
  - 身体动作幅度：`bodyX = -charge*12` → `×0.28 ×0.4 ≈ 1.3 CSS px` 的后坐（`motions.ts:53`、`rig.js:244`），实际尺寸下等于没有后坐。
- 用户会看到：屏幕内容「啪」地一下整体不见，然后一条静止的浅绿直线对着空白页面继续亮约 2 秒，怪兽几乎不动。
- 最小修改：① 把 `targets` 按与光束终点的距离排序，在 `markers.hit → markers.end` 区间内分批 `hideTarget`（每帧推进一个游标），而不是一次 `forEach`；② 对其中最靠近视口中心的 2~3 个目标复用 `prepareFracture/fracture` 生成碎片（数量受 `trimDebris` 的 72 上限约束，不新增依赖）；③ 每个目标消失时在 `fx` 追加一个 180ms 的尘埃圆/矩形淡出（复用 `attack()` 里 577 行那种内联 SVG 即可）；④ 把非 single 的 `duration` 从 4700 收到最后一个目标消失后 ≤400ms 结束，或把 `markers.end` 对齐到最后一批。
- 通过标准：FINAL_BLAST 期间每 200ms 截一帧，命中之后**不存在连续 >400ms 画面无变化**；最后一个目标消失与光束结束间隔 ≤400ms；截图中可辨认出至少 6 片来自被吐息清除内容的碎片。

### P0-2 废墟「看不见」：碎片被瞬移+缩到 30%+删掉大半，再被 93% 不透明底色盖住

- 位置：`session.ts` `settleDebris()`（331-352）、`trimDebris()`（323-330）、RUINS 的 `ruin-wash`（470-473）、`overlay.css:97-103`。
- 证据：
  - 每个目标**只保留前 2 片**，其余 `node.remove()` 直接消失（338-341）。爪击对正文最多切 8 行片（`fragments.ts:251`），也就是一次攻击之后不到 1 秒，6/8 的碎片会凭空不见。
  - 保留下来的片被 `Object.assign` 直接写 `left/top/transform`（342-347），**没有任何过渡**：从落点瞬移到地面行，并 `scale(.3)`。14px 正文缩到 ~4px，"可辨认的碎片"不再成立。
  - 排布是 `left = 20 + (index*89) % (innerWidth-190)`、`top = groundY-24-(index%3)*5`、`rotate(±8deg)` —— 等距、等大、同角度的一条带状序列，读起来像装饰条而非废墟堆。
  - 调用时机：`settleDebris()` 在 650ms 滚动**结束后**才执行（449-452），所以滚动过程中碎片是粘在视口不动、页面在其下方滑走，滚完再集体跳位——两次穿帮。
  - `trimDebris` 超过 72 片时整目标 `remove()`，同样无淡出（325-329）。
  - 进入 RUINS 后 1 秒内 `ruin-wash` 升到 `opacity 0.93` 的 `#eaf0e2` 全屏底色，等待回答期间一直保持。
- 用户会看到：攻击刚结束碎片就大批消失，剩下的一排小到看不出是什么的碎屑贴在底边；到了「停顿看废墟」这一刻，屏幕其实是一张近乎纯色的浅绿纸。目标 2 的「废墟可见」和用户原始诉求「文字图片变成可辨认的碎片和废墟」在这一步被抵消。
- 最小修改：① 把 `settleDebris` 的赋值改成一次 260~400ms 的 `clock.animate` 插值（或给节点加一次性 `transition`），缩放止于 0.55~0.7 而不是 0.3；② 保留数从 2 提到 3~4，并让 `left` 在目标原始 x 附近做 ±40px 抖动、`top` 允许 2~3 层堆叠，去掉等距条带；③ 移除时先 120ms 淡出再 `remove()`；④ `ruin-wash` 峰值降到 0.6~0.7，或改成自地面向上的线性渐变，让废墟带留在未被洗白的区域。
- 通过标准：AWAITING_ANSWER 的截图里能辨认出至少 3 段来自原页面的文字/图片内容；碎片落位有可见中间帧（非瞬移）；废墟带不呈等距等大排列。

### P1-3 归位读不出「刚才被破坏的内容回来了」：所有碎片一起飞向元素左上角

- 位置：`session.ts` `restore()`（673-700）。
- 证据：`f.node.style.translate = (rect.left - f.rect.left, rect.top - f.rect.top)`（695）。`rect` 是**整个原元素**的矩形，`f.rect` 是碎片当前矩形，于是一个段落的全部行片终点都是该段落的左上角同一点。`fracture()` 其实知道每片的 `region.left/top`（`page.ts:179-201`），但这个信息没有传到恢复阶段。同时 `showTarget` 按 `page.targets` 的**文档注册顺序**分批显形（698-699），与屏幕上碎片的位置无关；碎片 `opacity = 1-p` 从一开始就线性变淡。
- 用户会看到：一堆小碎屑从底边被「吸」到各段落的左上角同时淡掉，原文在另一条时间线上按文档序一块块亮起——两件事在视觉上对不上，更像清场特效而不是归位。
- 最小修改：① `fracture()` 时把 `region.left/top` 写进 `node.dataset`（或与 `target.fragments` 并行保存），`restore()` 终点改用 `rect.left + region.left / rect.top + region.top`；② 碎片透明度改成 `1 - clamp((p-0.75)/0.25)`，即先归位、末段再消失；③ `showTarget` 的顺序按 `target.rect.top` 排序，使显形自上而下与碎片回流同向。
- 通过标准：恢复进度 50% 的截图中，每片终点与其 `region` 原点偏差 ≤4px；碎片在 p<0.75 前保持可辨认；原文显形顺序与屏幕上下位置一致。

### P1-4 睡眠前怪兽瞬移到屏幕正中（并可能保持镜像）

- 位置：`session.ts` `restore()` → `this.positionDefault()`（720），`positionDefault`（274-288）。
- 证据：`positionDefault()` 直接写 `mount.style.left = innerWidth*0.5 - 124`，**无动画**；此时 `mount.style.transform` 可能仍是上一次攻击/吐息留下的 `scaleX(-1)`（302、591-595），`positionDefault` 不清；`.zzz` 固定放在 `innerWidth*0.5 + 60`（722），若角色镜像，z 字就落在尾巴一侧而不是头侧。
- 用户会看到：页面刚解锁的那一帧，怪兽从最后站位「闪现」到屏幕中间，然后才开始打哈欠淡出。方案写的是「怪兽留在角落入睡」。
- 最小修改：进入 SLEEPING 前用已有的 `moveTo(restLeft, mirror)` 滑过去（它已经带跳跃和影子补偿），或干脆不改 `left`、只按当前朝向把 `.zzz` 放到头部一侧；`positionDefault` 里显式设置 `transform`。
- 通过标准：SLEEPING 起始前后两帧角色位移 ≤4px，或该位移有 ≥250ms 的可见过渡；z 字始终出现在头部一侧。

### P2-5 音效事件映射有两处会被听出来的错位，破坏段缺收尾重音

- 位置：`src/audio/catalog.ts:20-28`、`session.ts:465-473`、`session.ts:717-718`。
- 证据：
  - `landing: ["tail0"]` —— **登场落地声与尾扫命中声是同一个文件**（`tail0.opus`，0.32s，来源 `impact-impactWood_heavy_000`）。方案允许复用素材，但复用到「与另一套动作的命中音完全同源」会让登场和尾扫听起来是同一件事。
  - 方案 4.2 要求摧毁配乐「循环段 + 短收尾重音 + 淡出」，而 `accent.opus` 只在**进入 SLEEPING** 时播（718）；DESTROYING→RUINS 的转场只有 `breathing`（466）+ 配乐 0.25s 淡出（`mixer.ts:216-221`），破坏段落是「断掉」而不是「收住」。
  - `settleDebris` 全程没有任何碎屑沉降音，方案 4.3「废墟：碎屑沉降」这一条目前没有事件。
  - 附带：尾扫虽然动作是 196° 大扫，但页面结果与爪击完全相同（同样只 `fracture` 一个目标），且 `preferred` 只按 `count % 4 === 3` 轮换（`session.ts:396`），与目标宽度无关 —— 「较宽结构用尾扫、成片破坏」未实现。
- 最小修改：① `landing` 改指向另一条已有重击素材（如 `claw0`）或与 `tail0` 做不同播放速率/增益，至少不共用同一 id；② 在 `phase("RUINS")` 前 200ms 内补一次 `audio("effect","accent")`；③ `settleDebris()` 触发时按组播一次 `debris`；④ 尾扫选择改为「目标宽度 > 视口宽度 0.5 时优先 tail」。
- 通过标准：事件表中 `landing` 与 `tail` 不共用文件；破坏→废墟转场存在 accent 计划；并在实际试听记录中确认（本条**必须有录音或人工试听记录**，不能用解码测试代替）。

## 待观察（证据不足，需要你补交的渲染帧）

这些我**不下结论**，请按清单导出后我复审：

1. **目标 1 的造型一致性**：概念图是 3/4 正面、双臂可见、浓眉圆眼；`rig.js` 的 SVG 是朝右略侧身、近/远侧各一眼一臂的另一套画法。二者是否是"同一只怪兽"，必须看 **248×208 实际尺寸**的渲染图（中立、爪击 610ms、尾扫 830ms、吐息 57%、睡眠 50%，正向与镜像各一套）。
2. **尾扫 z 序跳变**：`rig.js:241-243` 在 `tailR > 75` 的那一帧把尾巴整体挪到最前层。按关键帧插值，阈值大约发生在 ~700ms 和 ~1400ms 两处，此时尾巴正压在躯干/头部上方。请补这两个时刻各前后 2 帧。
3. **躯干前冲的髋部露缝**：爪击命中时 `bodyX=135`（躯干相对双腿横移 37.8 个 SVG 单位 ≈ 15 CSS px，`rig.js:244`），腿部做了反向补偿保持不动。请补命中帧的髋部特写。
4. **登场是否"从视口边缘进入"**：`motions.ts:39` 是 `frame.x = (1-smooth)*-220`，起点只在最终站位左侧 220px（1280 宽屏下约 x=416，仍在屏内），靠 `opacity = clamp(p*4)` 淡入。需要确认观感是"走进来"还是"凭空淡出现"。
5. **换位时的瞬间翻面**：`moveTo` 在 `distance < 2` 时也会先写 `scaleX(-1)` 再 return（302-303），相邻目标左右交替时可能出现无位移的原地翻面抖动。
6. **攻击带厚度**：按 rig 几何推算，爪尖与尾尖的命中高度几乎重合（容器内 y≈137 与 143，即地面线上方约 60px / 54px）。这意味着"攻击带"实际是一条 ~6px 宽的线，所有破坏都发生在视口底部同一条高度上。请确认长页推进时观感是否单调。
